# 2D VMC 配對與分區

製作器：https://anshaer.github.io/2D/maker.html
手機：https://anshaer.github.io/2D/mobile.html
平板：https://anshaer.github.io/2D/tablet.html
診斷：https://anshaer.github.io/2D/receiver.html

## 接收端

製作頁與匯出角色頁都勾「VMC 接收（手機／平板）」產生 12 碼，一維碼直接顯示，QR 按鈕點擊才彈出。
來源清單顯示來源與有效區域。VMC 啟用時停止電腦面部辨識，CPU／GPU 角色渲染仍可選擇。

## 傳送端

手機可選整個面部、頭部、眼睛、眉毛、嘴型；選區只決定接收控制權，手機仍由同一面部模型辨識。
平板不用相機，使用多點觸控滑桿及表情按鈕，預覽預設收合。面部放開歸零可自行選擇。
兩種傳送端都輸入同一碼，最多 8 台。

範例：手機頭部＋平板眼睛＋另一台平板嘴型。
整面來源可能占用所有部位，因此分工時要先選指定區域。

## 優先與失效

同區先連線、新鮮有效者優先。每來源只保留當前一份資料，3 秒未更新釋放，備援可以接手。
分區中的其他值不會覆蓋別區。失效且沒有備援的值回中性；全部來源失效清除面部狀態。
沒有累積影格／傳送計數。心跳與重連沿用現有協定；手動中斷會停止重連。

這是區域分工，不是多視角融合。不會校正不同相機的外參、時鐘或三維座標。
2D 不直接套用 3D 身體骨骼；保留原角色姿態與圖層邏輯。

## 方向事件

每個來源的方向事件重新編號後回覆原來源，避免兩台 seq 相同造成重複或誤回覆。
服裝／表情切換依專案圖片組配置；手機滑動與平板方向按鈕使用同樣規則。

## 協定

PeerJS Cloud 訊號服務，WebRTC DataChannel，protocol `ansha-vmc-osc/2`，配對 prefix `ansha-vmc2-`。
OSC 帶 Head、BlendShape、Apply、時間與 ANSHA 深度／辨識狀態；scope 是自訂外層控制訊息。
一般 UDP VMC 不能直接送到純網頁，需另做橋接。此 2D 方案不需要 Warudo 插件。
